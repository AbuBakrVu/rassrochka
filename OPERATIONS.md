по проекту. Обновляется по ходу работы, в отличие от `DEPLOY.md`

## Общий статус проекта (на 2026-08-12)

**Что это.** Nasiya (бывш. «Финора») — CRM для учёта рассрочек (BNPL) для
торговых компаний: сделки, клиенты, платежи, касса, соинвесторы,
сотрудники, аналитика. Стек: Next.js 16 (App Router) + TypeScript +
Postgres. Деплой — собственный сервер на клиента (не общий SaaS с
поддоменами), управляется CLI `./nasiya install|update|settings|status|backup`
поверх Docker Compose (`app` + `db` + `caddy`).

**Где сейчас (в проде).** Один реальный сервер развёрнут и работает:
домен `nasiya.ru`, компания на `bakr.nasiya.ru`, IP `193.233.91.46` (см.
таблицу ниже). Переезд с localStorage-прототипа на Postgres завершён
(с 2026-08-08) — это уже история, а не открытая задача.

**Что реально работает (полный список фич — `PROGRESS.md`/`PROGRESS_PRO.md`,
здесь только веха):** канбан сделок, карточка сделки (график, экономика,
реструктуризация, откат платежа, досрочное закрытие, смена ответственного,
удаление ошибочной сделки, печать договора/сводки), карточка клиента с
оценкой надёжности, приём платежа, касса, соинвесторы (доля от прибыли,
журнал капитала), сотрудники, аналитика (воронка, лесенка просрочки,
причины отказов), клиентский кабинет `/pay/<token>`, маршрут менеджера
`/route`, рассылки-напоминания через WhatsApp, панель владельца платформы
`/admin`, глобальный поиск.

**Что не работает / открыто прямо сейчас** — см. раздел «Статус по
открытым задачам» ниже; это текущий короткий список, а не всё, что
когда-либо было пробелом (полный исторический список — `PROGRESS.md`).

### Восстановление SSH-доступа (2026-08-12)

Пользователь прислал в чат `root`-пароль для входа по паролю. Доступ
восстановлен так: подобранный ранее ключ `~/.ssh/nasiya_admin` (созданный
до переустановки сервера) оказался всё ещё валидным на стороне клиента —
его публичную часть дописали в `~/.ssh/authorized_keys` на сервере через
разовый вход по паролю (через `sshpass`, поставлен через `brew install
sshpass`). Дальше — только по ключу, пароль больше не используется и
нигде не сохранён.

⚠️ **Пароль был передан открытым текстом в чате.** Рекомендация
пользователю: сменить root-пароль на сервере (`passwd`) и/или отключить
вход по паролю вовсе (`PasswordAuthentication no` в `sshd_config`) —
это как раз входит в задачу 5 (безопасность сервера), см. ниже.

### Учётные данные (актуальны на 2026-08-12, могли поменяться)

- Postgres: пользователь `nasiya`, пароль — в `/opt/nasiya/.env`
  (`PG_PASSWORD`), генерируется `./nasiya install` через `openssl rand -hex 24`
